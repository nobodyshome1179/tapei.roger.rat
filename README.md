# 有鼠請回答：城市急診檢傷與處方箋

[市政 debug 松](https://puma.taipei/hackathon)題目 #3「鼠患四處跑，衛生安全怎麼辦」的提案原型。以 Vue 3＋Vite（JavaScript）建置，由單檔 demo [public/original/demo_rat.html](public/original/demo_rat.html) 漸進轉換而來。

## 請先讀這段說明

- 本專案是參加者用 AI 協助製作的原型，與主辦單位無關，也不代表主辦單位或市府的立場。本文件只整理需求、資料與做法，不評價市府、任何政黨或任何人。
- 地圖上的通報、雨量、蛇類目擊、隊伍、店家、任務、點數與兌換品項大多是模擬資料，介面上標有「模擬資料」或「模擬」。行政區界與底圖（內政部國土測繪中心）是真實資料。
- 畫面中的臺北市政府 LINE 官方帳號只是模擬示意，用來說明市民怎麼收到通知，並非實際會使用的管道。
- 本文件使用以下標記：
  - **[實證]**：開放資料、法規或官方網頁，可以直接查證。
  - **[AI整理]**：AI 從新聞或民間網站整理，還沒有經過真人查核。
  - **[AI模擬]**：AI 的設計、估算或假設，供討論用。
- 標「（原型未呈現）」的項目是提案的設計，目前的畫面還沒有做出來。

- 題目來源：[市政 debug 松題目 #3「鼠患四處跑，衛生安全怎麼辦」](https://puma.taipei/hackathon#issue-3)

## 這個專案在做什麼

城市有鼠患，先檢傷，再開處方；市府、店家、市民，各自做對的事：

- **檢傷**：地圖整合開放資料、通報與現場觀察，把每個 350 公尺區塊分成五級，決定先處理哪裡、派給誰。
- **處方箋**：每個區塊開出改善處方，並追蹤從審核到覆核的進度。
- **社區參與**：市民觀察與回報，店家做好自己的後場，受訓的社區防鼠巡查員確認鼠跡；投藥與鼠屍處理只交給專業人員。

## 解法與取捨

### 解法對照

各解法方向在本專案的做法如下。

| 解法方向 | 本專案的做法 |
| --- | --- |
| 鼠患風險地圖與防治排序 | Gi* 熱點、風險與傳播、五級檢傷；對外只呈現三級區域風險，只到格子與區域，不標出個別店家 |
| 垃圾與廚餘的密封收集與收運調整 | 垃圾停收週的提醒；處方箋的「收運調整」；店家三不（廚餘密閉）；垃圾代收任務 |
| 下水道與側溝的修補、清淤與接管 | 雨水人孔密度、低窪程度作為風險因子；通報說明的「水溝下水道」線索；巡查員的鼠跡確認，提供衛工處與水利處排序參考 |
| 分區同步防治與安全投藥 | 市民不投放鼠餌或藥物；餌站與捕鼠籠設在投藥區，市民每週觀察並記錄狀態（含毒餌外露、其他動物在吃或進出）；A／B／C 安全分級；投藥區的二次中毒提醒 |
| 社區、店家與學校的防鼠診斷與輔導 | 社區環境衛生師到場診斷（現行為「鼠類偵防師」）；三不防鼠店家認證，主動通報不扣分；老公寓整棟參與（原型未呈現） |
| 鼠患通報與防治進度公開 | 處方箋的五個執行階段公開；志工任務以拍照回報、市府驗收；主動通知市民的流程以 LINE 畫面模擬示意 |

### 衝突的處理

| 衝突 | 本專案的設計選擇 |
| --- | --- |
| 投藥 vs 飼主、家長與動保團體 | 市民只觀察、不投藥；餌站的觀察紀錄會標出毒餌外露與非目標動物，讓主責單位及時處理；地圖提示投藥區的二次中毒風險 |
| 先輔導還是先開罰 | 三不店家認證：主動通報、主動改善都不扣分；被爆料且事前沒有通報，才暫停認證 |
| 地圖要公開到多細 | 地圖只到 350 公尺格子與行政區，不點名店家；店家只公開自願加入認證的 |
| 全區同步還是集中熱點 | 「可能擴散範圍」依老鼠的擴散距離計算，把相鄰的高風險格子排在一起；「特攻」檢視的人力缺口疊圖讓鄰近隊伍支援 |
| 夜宿者與清消 | 無家者的參與以自願、輕度、按次支薪、社工陪同為原則；地圖不標示無家者的位置與身分（原型未呈現） |

### 特別關注族群

| 特別關注 | 本專案怎麼處理 |
| --- | --- |
| 高齡 | 長者以防鼠志工參與觀察與巡查，作為社會參與；老公寓整棟參與，不必自己爬高封堵（原型未呈現） |
| 身心障礙 | 【待補：鼠餌盒與密封垃圾桶不擋人行道與導盲磚的檢查項目】 |
| 兒童與照顧者 | 市民不碰毒餌；餌站位置與「毒餌外露」的觀察紀錄讓家長知道哪裡要小心 |
| 外籍 | 【待補：介面、通報與投藥警告的多語版本】 |
| 經濟弱勢 | 無家者參與的四項原則；清消前由社工告知（原型未呈現） |

## 功能

### 開場

開場畫面顯示本週分級的通報數、要派案的區塊數與其中的 1 級爆發數，並提供三個入口：

- **我是市民**：查看附近風險、接協助任務，也能直接通報。
- **我是店家**：照著城市處方箋改善，複核後取得防鼠標章。
- **我是市府**：整合全市資料檢傷排序，調度各局處處理源頭。

入口下方另有「先看市民怎麼從 LINE 收到通知」，開啟 LINE 市民端的模擬導覽。

### 三種身分

| 身分 | 面板分頁 | 看到什麼 | 可以做什麼 |
| --- | --- | --- | --- |
| 市民 | 任務、我的 | 附近的區域風險（三級）、可認領的任務、餌站與捕鼠籠 | 通報老鼠、每週觀察餌站與捕鼠籠、清潔與垃圾代收、累積點數與兌換 |
| 店家 | 我的店、排行、提醒 | 自己所在區塊的風險、標章進度與排名、市府通知 | 三不自評、申請認證、主動通報 |
| 市府 | 派案、總覽、餌站、試判 | 全市檢傷、派案清單、處方箋進度 | 依級別篩選區塊、審核處方箋、派案、驗收志工任務、在地圖上選點試判 |

- 派案清單分成區塊派案、市民通報、志工任務。
- 頂列的「分級規則」開啟規則頁：市府內部用五級判斷單一案件的急迫性，對民眾與店家用三級呈現區域整體風險。

### 地圖檢視（市府）

檢傷、熱點、趨勢、蛇鼠、餌站、風險、點位、特攻，共 8 種。下方時間軸可以逐週播放；地圖左上的摘要卡顯示本週的五級分布、雨量、均溫、停收天數、搜尋關注度、本週事件與建議。

### 五級檢傷

| 級別 | 名稱 | 派案對象 |
| --- | --- | --- |
| 1 | 緊急處置 | 市府跨局處統籌 |
| 2 | 優先處理 | 市府權責單位 |
| 3 | 一般處理 | 市府權責單位 |
| 4 | 追蹤觀察 | 市府監測窗口 |
| 5 | 紀錄與衛教 | 市府監測窗口 |

每個區塊列出危險因子的原因、事件屬性與分數加成（嚴重度明細）。

超商視為比餐飲低一級的食物源，只影響區塊風險，最多加 2 個百分位；食物源已在全市前 10% 的區塊不加，避免和市場、夜市重複計算 [AI模擬]。超商也是人潮聚集的地方，周邊通報多可能只是看到的人多，所以不加在單筆通報的嚴重度。位置來自 OpenStreetMap，內用區、熱食等設施沒有開放資料，為模擬。

### 城市處方箋

處方箋依序經過五個階段：待審核、已核准派案、單位執行中、改善完成・待覆核、覆核通過・持續監測。處方箋是 AI 輔助的建議，權責需要由政府確認。

### 安全分級

| 等級 | 誰可以做 | 工作內容 |
| --- | --- | --- |
| A | 防鼠志工（市民）、店家 | 清潔、垃圾代收、店家輔導、觀察餌站。不碰老鼠、鼠屍、鼠糞與毒餌 |
| B | 社區防鼠巡查員（受訓） | 鼠跡確認、捕鼠籠的檢查與記錄。戴手套與口罩 |
| C | 社區環境衛生師或合格病媒防治人員 | 投藥、處理鼠屍、清理鼠糞（先用稀釋漂白水噴濕，不可乾掃） |

「社區環境衛生師」「社區防鼠巡查員」「防鼠志工」是本專案建議的頭銜；「打鼠特攻隊」是社區隊伍的號召名稱。提到臺北市現行計畫時，仍用原名「鼠類偵防師」。

### 店家標章

| 標章 | 條件 |
| --- | --- |
| 三不防鼠認證 | 不留食物、不留孔洞、不堆雜物；現場評核通過即取得 |
| 防鼠守護店 | 已認證，且連續 90 天巡查良好、主動通報零隱匿 |
| 米奇零推薦 | 年度推薦榜：連續一年良好 |

連續兩次巡查有鼠跡會降一級並輔導改善。標章承諾的是主動、透明、持續改善，不是零老鼠。後兩級的獎勵措施尚待主管機關評估與局處協商。

### 點數

點數有三種用法：到兌換點換垃圾袋、洗碗精等小物；累積簽到取得里民活動的優先登記資格；集滿 12 區寶石換實體徽章。兌換點、品項與點數都是模擬，正式規則需由市府訂定。

### 手機畫面與 LINE 示意

- 桌機的頂列有「手機」按鈕（快捷鍵 L），開啟手機畫面，分成 LINE 通知、市民、店家三個分頁。可以直接操作，市府端通知店家後，店家分頁會同步更新。
- LINE 的畫面是獨立的示意頁 [public/line-oa.html](public/line-oa.html)：`?demo` 是開場的市民導覽，`?phone` 是手機畫面裡的 LINE 分頁。
- 其中的臺北市政府 LINE 官方帳號只是模擬示意，並非實際會使用的管道，也沒有介接任何真實帳號。

### 其他

- 首頁與市府地圖角落的起司圖示，會開啟講者用的說明圖。
- 市民與店家的地圖使用槌子游標，不時會跑出老鼠可以敲🔨。

### 模擬的部分

隊伍、店家、任務狀態、點數與兌換品項、超商設施、雨量與氣溫、搜尋關注度、蛇類目擊，以及預設的通報資料，都是模擬。

### 方法重點

模型沿用「北市鼠情週報」的分析（[src/lib/od.js](src/lib/od.js)），檢傷概念沿用「鼠患檢傷站」（[src/lib/model.js](src/lib/model.js)）。

- **熱點**：350 公尺六角格、近 4 週通報、Getis-Ord Gi*。用模擬的真實鼠量評分，350 公尺在 250、350、500 公尺中最平衡（F1 0.51）[AI模擬]。1 級門檻另外加嚴，要求 Gi* 99% 顯著。
- **人口校正**：人多的地方通報也多，可以改用每人通報量計算。在模擬資料上效果有好有壞，原型沿用週報的預設，不做人口校正。
- **老鼠活動範圍**：依文獻，都市溝鼠的親屬多在 33 公尺內，軸向擴散約 62 公尺。通報依約 45 公尺分攤到附近格子，風險擴散依 8 週約 100 公尺換算 [AI模擬]。
- **通報不等於鼠量**：通報反映的是「誰看見並願意說」。成效應該看鼠跡指數、足跡板與捕獲率，不看陳情件數；這些監測資料目前沒有公開。

## 執行方式

需要 Node.js 20.19 以上或 22.12 以上（Vite 8 的要求）。

```bash
npm ci
npm run dev             # 開發模式，網址顯示在終端機
npm run dev -- --host   # 手機連同一個 Wi-Fi 測試時用，終端機會多顯示區網網址
npm run build           # 建置到 dist/（網站、public/ 的檔案與第三方授權清單）
npm run preview         # 預覽 dist/
```

- `dist/` 的檔案要用網頁伺服器開啟（瀏覽器不允許從檔案直接載入模組）。`vite.config.js` 設定 `base: './'`，所以放在任何子目錄都能開。
- 底圖（國土測繪中心電子地圖）與字型（Google Fonts）需要網路。
- 建置時會出現 JS 超過 500 kB 的警告，主要是 `od.js` 內含的模擬資料，不影響使用。

### 開發注意事項

- `app.js` 直接操作 DOM、掛全域事件，熱更新會重複初始化，所以 JS 有改動時整頁重新載入；CSS 照常熱更新。
- 建置時的 CSS 壓縮會丟掉排在 `-webkit-` 版之前的無前綴屬性。同一個屬性有前綴版時，前綴版要寫在前面。

    catalog.js             點數兌換的品項、地點與庫存（模擬），換位置用的行政區地標
    whack.js               槌子游標與打地鼠彩蛋
    slides.js              講者用說明圖
  lib/
    od.js                  北市鼠情週報的模擬資料、350 公尺六角格、Gi* 熱點與風險（已壓縮，原樣沿用）
    model.js               檢傷模型：五級檢傷、派案對象、通報的 AI 判讀（以規則模擬）
    dataKit.js             瀏覽器端的開放資料匯入（CSV → 資料包）

    cvs-osm.json           OpenStreetMap 的超商位置（只有經緯度，ODbL 授權）

  assets/                  品牌圖示、老鼠游標與插圖、講者說明圖

## 從 demo 轉換到 Vue＋Vite

轉換依據是 2026-10-24 13:18 版的 `public/original/demo_rat.html`。原則是先搬家、行為不變，再逐步元件化：

- **Leaflet**：原本內嵌的 Leaflet 1.9.4 改用 npm 套件，版本相同。
- **程式**：原本的內嵌 script 拆成 ES 模組，邏輯沒有改。主程式的立即執行函式原樣包成 `initApp()`，打地鼠與說明圖分別是 `initWhack()`、`initSlides()`，啟動順序和原本的 script 相同；介面用語與兌換品項另外抽成 `terms.js`、`catalog.js`。
- **標記**：Vue 元件只提供畫面骨架（各區塊的 id），面板內容仍由 `app.js` 以 innerHTML 產生。
- **樣式**：依原本的順序載入，後面的會覆蓋前面的。
- **驗證**：用 Playwright 對原檔與新版做截圖與計算後樣式比對，兩版畫面一致。

`public/original/demo_rat.html` 之後如果再修改，要手動移植到 `src/`。開發模式與建置後都可以用 `/original/demo_rat.html` 開啟原檔，方便和新版並排比對。

## 換成真實資料

[src/lib/dataKit.js](src/lib/dataKit.js) 可以在瀏覽器裡把開放資料 CSV 轉成資料包，檔案只在這台裝置上處理。它依欄位名稱判斷資料種類，支援 Big5、民國年與 TWD97，並以臺北的經緯度範圍篩選位置。

- 匯入面板（`#p-data`）的程式還在，但目前的介面沒有入口。開發時可以選「我是市府」進入地圖，再在瀏覽器主控台執行 `ratTriage.setTab('p-data')` 叫出。
- 面板文字提到的 `scripts/prepare-data.mjs`（離線整理資料包的腳本）不在本儲存庫。

使用真實資料前請注意：

- 1999 的鼠患案件以類別名稱含「鼠」或「病媒」篩選。2026 年 7–9 月的資料中沒有這類次類別（2026-10-23 存取）。【待補：研考會確認鼠患通報放在哪些次類別】
- 食品業者登錄數只有全市總數，無法分配到行政區。食物源請改用市場、夜市、超商等地點的 CSV（名稱、類別、經緯度）。
- 見鼠地圖的說明欄只轉成 7 種線索標籤，不保留原文；使用前請先確認網站的資料使用條件。

## 隱私與資安

- 原型沒有後端，計算都在瀏覽器內完成；匯入的 CSV 不會上傳。
- 部署在 Vercel 的網站使用 Vercel Web Analytics 統計瀏覽量，瀏覽紀錄會傳到 Vercel。只在正式建置啟用，開發模式與手機面板內嵌的頁面不計；`public/` 裡的靜態頁（原型、LINE 示意頁）沒有加統計。
- 志工與市民的照片在原型中只是示意，沒有實際上傳。正式版若要辨識照片內容，AI 模型必須部署在內部環境。
- 地圖只到區塊與行政區，不點名店家，也不標示無家者。
- 市民通報與通知以降低個資綁定、提高通報意願為原則。原型中的臺北市政府 LINE 官方帳號只是模擬示意，並非實際會使用的管道。
- 版本固定：相依套件都鎖定確切版本。
- 正式上線前，需依所屬單位的資安規範審查。
